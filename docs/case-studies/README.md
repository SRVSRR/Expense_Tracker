# Project Case Studies

Five focused reads for data-science and data-engineering roles. Each follows the same structure:

**Problem → Approach → Stack → Results → Lessons**

## Reading guide

| Read this first | If you want proof of |
|---|---|
| [Trustworthy finance API](01-trustworthy-finance-api.md) | Testing, correctness, isolation, and backend reliability |
| [Supabase Auth migration](02-supabase-auth-migration.md) | Secure migrations, schema evolution, and rollback planning |
| [Transaction categorization](03-ml-transaction-categorization.md) | Applied classification and cold-start handling |
| [Cash-flow forecasting](04-ml-cash-flow-forecasting.md) | Time-series modeling and uncertainty |
| [Production analytics platform](05-production-analytics-platform.md) | Caching, deployment, documentation, and client handoff |

## Recommended paths

- **Data scientist:** start with studies 3 and 4, then read study 1 for testing discipline.
- **Data engineer:** start with studies 1 and 5, then read study 2 for migration discipline.
- **Hiring manager:** read study 1 for engineering judgment, then either study 3 or 4 for ML judgment.

## Evidence standard

Each study links to the implementation, tests, migrations, or operational documentation it describes. They intentionally avoid invented performance numbers: where production metrics are unavailable, the stated results are the verified behaviors, tests, schemas, and deployment contracts in this repository.
